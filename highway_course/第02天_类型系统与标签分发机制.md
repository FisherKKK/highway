## 1. 为什么需要标签系统？

### 1.1 问题引入

在传统C++模板编程中，我们可能这样定义向量：

```cpp
// 问题方案：直接使用模板参数
template<typename T, int N>
struct Vector {
    T data[N];
};

Vector<float, 4> v1;  // SSE
Vector<float, 8> v2;  // AVX
```

**这种方案的问题：**
1. ARM SVE等可扩展向量的大小在编译时未知
2. 函数重载困难（模板参数不能用于重载）
3. 无法在运行时改变向量大小

### 1.2 Highway的解决方案

Highway使用**零大小的标签类型**作为"类型描述符"：

```cpp
// Highway方案：使用标签分发
template <typename Lane, size_t N, int kPow2>
struct Simd {
    // 这个类型大小为0！
    constexpr Simd() = default;

    using T = Lane;  // 车道类型
    // ... 元数据
};

// 使用标签来选择函数
template <class D>
Vec<D> Load(D d, const TFromD<D>* ptr);
```

**优势：**
- 标签在编译后完全消失（零大小优化）
- 可以用标签进行函数重载
- 支持可扩展向量（大小运行时确定）

## 2. 深入 Simd<T, N, kPow2>

### 2.1 三个模板参数的含义

打开 `hwy/ops/shared-inl.h`，找到Simd的定义：

```cpp
template <typename Lane, size_t N, int kPow2>
struct Simd {
    using T = Lane;

    // 实际车道数计算
    static constexpr size_t kLanes = detail::ScaleByPower(N, kPow2);

    // ...
};
```

**参数解释：**

| 参数 | 含义 | 示例 |
|------|------|------|
| `Lane` | 车道元素类型 | `float`, `int32_t`, `uint8_t` |
| `N` | "全"向量的车道数 | 通常是 `HWY_LANES(T)` |
| `kPow2` | 2的幂次缩放因子 | -1=半向量, 0=全向量, 1=双向量 |

**实际车道数：** `Lanes(d) = N * 2^kPow2`

### 2.2 可视化理解

```
对于 float 类型：

Simd<float, 4, -2>  →  1 个float   (4 * 2^-2 = 1)
Simd<float, 4, -1>  →  2 个float   (4 * 2^-1 = 2)
Simd<float, 4,  0>  →  4 个float   (4 * 2^0  = 4)  ← 全向量
Simd<float, 4,  1>  →  8 个float   (4 * 2^1  = 8)  ← 双向量
Simd<float, 4,  2>  → 16 个float   (4 * 2^2  = 16) ← 四向量
```

## 3. 标签的便利别名

### 3.1 查看标签定义

```cpp
// hwy/ops/shared-inl.h

// 1. ScalableTag - 使用全向量
template <typename T, int kPow2 = 0>
using ScalableTag = Simd<T, HWY_LANES(T), kPow2>;

// 2. CappedTag - 车道数上限
template <typename T, size_t kLimit, int kPow2 = 0>
using CappedTag = Simd<T, HWY_MIN(HWY_LANES(T), kLimit), kPow2>;

// 3. FixedTag - 固定车道数（必须是2的幂）
template <typename T, size_t kNumLanes>
using FixedTag = Simd<T, kNumLanes, 0>;
```

### 3.2 使用场景

```cpp
// 场景1: 最大化性能 - 使用全向量
void ProcessFull(const float* in, float* out, size_t n) {
    const ScalableTag<float> d;  // 尽可能大的向量
    // SSE: 4 lanes, AVX2: 8 lanes, AVX-512: 16 lanes
}

// 场景2: 限制向量大小 - 处理小数组
void ProcessSmall(const float* in, float* out) {
    const CappedTag<float, 4> d;  // 最多4个lanes
    // 即使在AVX-512上也只用4 lanes
}

// 场景3: 固定大小 - 特定算法要求
void ProcessFixed(const float* in, float* out) {
    const FixedTag<float, 8> d;  // 恰好8个lanes
    // 如果硬件不支持，编译失败
}
```

## 4. 类型重绑定 (Rebind)

### 4.1 为什么需要Rebind？

在SIMD编程中，经常需要在不同类型之间转换：

```cpp
// 场景：将float向量转换为int向量
const ScalableTag<float> df;
auto vf = Load(df, float_array);

// 需要相同大小的int向量
const Rebind<int32_t, decltype(df)> di;
auto vi = ConvertTo(di, vf);
```

### 4.2 Rebind的实现

查看源码：

```cpp
// hwy/ops/shared-inl.h
template <typename T>
struct Simd {
    // 重新绑定到新类型NewT
    template <typename NewT>
    using Rebind = Simd<NewT,
                        NewN<RebindPow2<NewT>(), kPrivateLanes>(),
                        RebindPow2<NewT>()>;

    // 重新绑定到新kPow2
    using Half = Simd<T, N, kPow2 - 1>;
    using Twice = Simd<T, N, kPow2 + 1>;
};
```

### 4.3 复杂的Rebind逻辑

**问题：** 当元素大小改变时，如何保持向量大小一致？

```
情况1: float → int32_t (都是4字节)
  Simd<float, 4, 0> → Simd<int32_t, 4, 0>
  ✓ 车道数相同

情况2: uint8_t → uint32_t (1字节 → 4字节)
  Simd<uint8_t, 16, 0> → Simd<uint32_t, 4, 0>
  ✓ 字节数相同，但车道数减少4倍

情况3: uint32_t → uint8_t (4字节 → 1字节)
  Simd<uint32_t, 4, 0> → Simd<uint8_t, 16, 0>
  ✓ 字节数相同，但车道数增加4倍
```

**解决方案：使用分数编码**

```cpp
// hwy/ops/shared-inl.h
namespace detail {

// 当N不是整数时，使用固定点编码
// 高位存储分子，低20位存储分母
constexpr size_t Frac(size_t n, size_t d) {
    return (n << 20) | d;
}

}  // namespace detail
```

### 4.4 Rebind示例

```cpp
#include "hwy/highway.h"
namespace hn = hwy::HWY_NAMESPACE;

void RebindExample() {
    const hn::ScalableTag<uint8_t> d8;

    // 重绑定到更大的类型
    const hn::Rebind<uint32_t, decltype(d8)> d32;

    // 字节数保持相同
    // 如果d8有16个uint8_t (16字节)
    // 那么d32有4个uint32_t (16字节)

    std::cout << "uint8 lanes: " << hn::Lanes(d8) << "\n";
    std::cout << "uint32 lanes: " << hn::Lanes(d32) << "\n";
}
```

## 5. 标签的内部类型别名

### 5.1 查看Simd类的完整定义

```cpp
// hwy/ops/shared-inl.h
template <typename Lane, size_t N, int kPow2>
struct Simd {
    using T = Lane;  // 元素类型

    // 有符号/无符号变体
    using TN = MakeNarrow<T>;   // 窄化类型
    using TW = MakeWide<T>;     // 加宽类型
    using TS = MakeSigned<T>;   // 有符号版本
    using TU = MakeUnsigned<T>; // 无符号版本

    // 特殊重绑定
    using TFromD = T;  // 从标签获取类型
};
```

### 5.2 常用类型别名

```cpp
// 从标签D获取各种类型
template <class D>
using TFromD = typename D::T;  // 元素类型

template <class D>
using VFromD = Vec<D>;  // 向量类型

template <class D>
using MFromD = Mask<D>;  // 掩码类型

// 示例
const ScalableTag<float> df;
using T = TFromD<decltype(df)>;      // float
using V = VFromD<decltype(df)>;      // Vec128<float>等
using M = MFromD<decltype(df)>;      // Mask128<float>等
```

## 7. SFINAE与条件编译

### 7.1 HWY_IF_* 宏家族

Highway使用SFINAE（Substitution Failure Is Not An Error）来实现编译时函数重载：

```cpp
// hwy/base.h
#define HWY_IF_FLOAT(T) \
    hwy::EnableIf<hwy::IsFloat<T>()>* = nullptr

#define HWY_IF_SIGNED(T) \
    hwy::EnableIf<hwy::IsSigned<T>() && !hwy::IsFloat<T>()>* = nullptr

#define HWY_IF_UNSIGNED(T) \
    hwy::EnableIf<!hwy::IsSigned<T>()>* = nullptr
```

### 7.2 基于标签的条件编译

```cpp
// hwy/ops/shared-inl.h
#define HWY_IF_FLOAT_D(D) \
    HWY_IF_FLOAT(TFromD<D>)

#define HWY_IF_UNSIGNED_D(D) \
    HWY_IF_UNSIGNED(TFromD<D>)

// 使用示例
template <class D, HWY_IF_FLOAT_D(D)>
VFromD<D> Sqrt(D d, VFromD<D> v);  // 仅对float启用

template <class D, HWY_IF_UNSIGNED_D(D)>
VFromD<D> PopCount(D d, VFromD<D> v);  // 仅对unsigned启用
```

## 9. 标签系统的设计优势总结

### 9.1 为什么不用传统模板？

| 方案 | 优点 | 缺点 |
|------|------|------|
| **传统模板** `Vec<T,N>` | 简单直观 | 不支持可扩展向量<br>难以重载 |
| **Highway标签** `Simd<T,N,kPow2>` | 支持可扩展向量<br>零成本<br>易于重载 | 概念复杂<br>学习曲线陡 |

### 9.2 标签系统的核心价值

1. **统一接口**：同一个函数签名适用于所有平台
2. **零成本**：标签在编译后完全消失
3. **类型安全**：编译时检查所有类型错误
4. **可扩展**：支持未来的新SIMD架构
