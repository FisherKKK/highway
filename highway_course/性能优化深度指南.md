## 1. CPU 微架构基础

### 1.1 流水线与超标量执行

#### 现代 CPU 的流水线

```
┌──────────┬──────────┬──────────┬──────────┬──────────┬──────────┐
│  取指令  │  解码    │  重命名  │  执行    │  写回    │  退休    │
│  Fetch   │  Decode  │  Rename  │ Execute  │WriteBack │ Retire   │
└──────────┴──────────┴──────────┴──────────┴──────────┴──────────┘

多发射（超标量）：
  每个周期可以同时取多条指令
  乱序执行：指令可以不按顺序执行
```

#### Intel Skylake 的执行端口

```
                    ┌─────────────────┐
                    │   微指令队列     │
                    └────────┬────────┘
                             │
        ┌────────────────────┼────────────────────┐
        │                    │                    │
    ┌───▼───┐  ┌───▼───┐  ┌───▼───┐  ┌───▼───┐
    │ Port0 │  │ Port1 │  │ Port2 │  │ Port3 │  ... Port7
    └───┬───┘  └───┬───┘  └───┬───┘  └───┬───┘
        │          │          │          │
    ALU/FMA    ALU/FMA    Load      Load/Store
    Vector     Vector     Address   Address
```

**关键概念**：
- **Port 0/1**: 执行算术运算（整数、浮点、SIMD）
- **Port 2/3**: 加载数据（Load）
- **Port 4**: 存储地址（Store Address）
- **Port 7**: 存储数据（Store Data）

#### 吞吐量 vs 延迟

| 概念 | 定义 | 示例 |
|------|------|------|
| **延迟 (Latency)** | 单个操作从开始到完成的时间 | `VADDPS` (AVX): 4 cycles |
| **吞吐量 (Throughput)** | 单位时间内可以开始多少个操作 | `VADDPS`: 2 per cycle (Port 0 + Port 1) |

**优化策略**：
```cpp
// 差的代码：依赖链长，受延迟限制
auto a = Load(d, p);
a = Add(a, a);  // 等待 Load 完成
a = Mul(a, a);  // 等待 Add 完成
a = Add(a, a);  // 等待 Mul 完成

// 好的代码：独立操作，受吞吐量限制
auto a = Load(d, p1);
auto b = Load(d, p2);
auto c = Load(d, p3);
a = Add(a, a);  // 可以与其他操作并行
b = Mul(b, b);
c = Add(c, c);
```

### 1.2 指令延迟表（Intel Skylake）

| 指令 | 延迟 | 倒数吞吐量 | 执行端口 |
|------|------|------------|----------|
| `VADDPS ymm` | 4 | 0.5 | p0/p1 |
| `VMULPS ymm` | 4 | 0.5 | p0/p1 |
| `VFMADD*PS ymm` | 4 | 0.5 | p0/p1 |
| `VDIVPS ymm` | 13-14 | 5 | p0 |
| `VSQRTPS ymm` | 12 | 6 | p0 |
| `VMOVAPS ymm, mem` | ~5 | 0.5 | p2/p3 |
| `VMOVAPS mem, ymm` | ~1 | 1 | p4+p7 |
| `VPSHUFB ymm` | 1 | 1 | p5 |
| `VPERM2F128 ymm` | 3 | 1 | p5 |

**解读**：
- **VADDPS 延迟 4**: 结果在 4 个周期后可用
- **倒数吞吐量 0.5**: 每个周期可以启动 2 个 VADDPS（Port 0 和 Port 1）
- **VDIVPS 延迟 13**: 非常慢，应该避免

### 1.3 依赖链分析

#### 示例：点积计算

```cpp
// 版本 1: 长依赖链（差）
float DotProduct_V1(const float* a, const float* b, size_t count) {
  const ScalableTag<float> d;
  const size_t N = Lanes(d);

  auto sum = Zero(d);  // 初始化累加器

  for (size_t i = 0; i < count; i += N) {
    auto va = Load(d, &a[i]);
    auto vb = Load(d, &b[i]);
    auto prod = Mul(va, vb);
    sum = Add(sum, prod);  // ← 依赖前一次迭代的 sum
  }

  return GetLane(SumOfLanes(d, sum));
}

// 依赖链：
// sum[i] = sum[i-1] + prod[i]
//          ^^^^^^^^ 依赖前一次迭代
// 关键路径延迟：Load(5) + Mul(4) + Add(4) = 13 cycles/迭代
```

```cpp
// 版本 2: 多个累加器（好）
float DotProduct_V2(const float* a, const float* b, size_t count) {
  const ScalableTag<float> d;
  const size_t N = Lanes(d);

  // 4 个独立的累加器
  auto sum0 = Zero(d);
  auto sum1 = Zero(d);
  auto sum2 = Zero(d);
  auto sum3 = Zero(d);

  size_t i = 0;
  for (; i + 4*N <= count; i += 4*N) {
    auto va0 = Load(d, &a[i + 0*N]);
    auto vb0 = Load(d, &b[i + 0*N]);
    auto va1 = Load(d, &a[i + 1*N]);
    auto vb1 = Load(d, &b[i + 1*N]);
    auto va2 = Load(d, &a[i + 2*N]);
    auto vb2 = Load(d, &b[i + 2*N]);
    auto va3 = Load(d, &a[i + 3*N]);
    auto vb3 = Load(d, &b[i + 3*N]);

    sum0 = MulAdd(va0, vb0, sum0);  // 4 个独立的累加器
    sum1 = MulAdd(va1, vb1, sum1);  // 可以并行执行
    sum2 = MulAdd(va2, vb2, sum2);
    sum3 = MulAdd(va3, vb3, sum3);
  }

  // 合并累加器
  auto sum01 = Add(sum0, sum1);
  auto sum23 = Add(sum2, sum3);
  auto sum = Add(sum01, sum23);

  // 处理余项...

  return GetLane(SumOfLanes(d, sum));
}

// 4 个累加器打破了依赖链
// 理论加速比：4x（如果内存带宽足够）
// 实际加速比：2-3x（受内存限制）
```

**性能对比**（1M 元素，AVX2）：
- 版本 1: ~2.5 ms （受 FMA 延迟限制）
- 版本 2: ~0.9 ms （受内存带宽限制）
- 加速比: 2.8x

## 2. SIMD 性能模型

### 2.1 Roofline 模型

Roofline 模型帮助理解程序是受计算限制还是内存限制。

```
性能 (GFLOPS)
    │
    │         ╱─────────────────  ← 计算峰值（受 FMA 吞吐量限制）
    │       ╱
    │     ╱ 斜率 = 内存带宽
    │   ╱
    │ ╱
    └─────────────────────────> 算术强度 (FLOPS/Byte)
                                操作数重用次数
```

**算术强度 (Arithmetic Intensity)**：
```
AI = 总浮点操作数 / 总内存访问字节数
```

**示例**：
```cpp
// 向量加法：c[i] = a[i] + b[i]
// - 读取：2 * N * 4 字节（a 和 b）
// - 写入：1 * N * 4 字节（c）
// - 计算：N 次加法（N FLOPS）
// AI = N / (3 * N * 4) = 1/12 ≈ 0.083 FLOPS/Byte
// → 内存受限

// 点积：sum += a[i] * b[i]
// - 读取：2 * N * 4 字节
// - 写入：0 字节（累加到寄存器）
// - 计算：2 * N FLOPS（乘法 + 加法）
// AI = 2N / (2 * N * 4) = 1/4 = 0.25 FLOPS/Byte
// → 仍然内存受限

// 矩阵乘法：C = A * B (N x N)
// - 读取：~N^2 * 8 字节（简化）
// - 计算：2 * N^3 FLOPS
// AI = 2N^3 / (N^2 * 8) = N/4
// → 当 N 较大时，计算受限
```

### 2.2 内存带宽计算

**理论峰值带宽**：
```
带宽 = 通道数 × 每通道位宽 × 内存频率

DDR4-3200 (双通道)：
= 2 通道 × 64 bit × 3200 MT/s
= 2 × 8 字节 × 3200 MHz
= 51.2 GB/s
```

**实际可达带宽**：
- 顺序访问：~40-45 GB/s（85-90% 峰值）
- 随机访问：~5-10 GB/s（严重下降）

**测量带宽**：
```cpp
#include <chrono>
#include "hwy/highway.h"

void MeasureBandwidth(float* data, size_t size_bytes) {
  const ScalableTag<float> d;
  const size_t N = Lanes(d);
  const size_t count = size_bytes / sizeof(float);

  auto start = std::chrono::high_resolution_clock::now();

  // 简单的流式访问
  for (size_t iter = 0; iter < 100; ++iter) {
    for (size_t i = 0; i < count; i += N) {
      auto v = Load(d, &data[i]);
      Store(v, d, &data[i]);  // 读 + 写
    }
  }

  auto end = std::chrono::high_resolution_clock::now();
  double seconds = std::chrono::duration<double>(end - start).count();

  double gb = (size_bytes * 2.0 * 100.0) / 1e9;  // 读 + 写
  double bandwidth = gb / seconds;

  printf("Bandwidth: %.2f GB/s\n", bandwidth);
}
```

### 2.3 计算峰值

**理论峰值（AVX2, 一个核心）**：
```
FMA: a * b + c = 2 FLOPS
AVX2: 256-bit = 8 个 float
频率: 3.5 GHz
端口: 2 个 FMA 单元（Port 0 + Port 1）

峰值 = 2 FMA × 8 lanes × 2 ports × 3.5 GHz
     = 2 × 8 × 2 × 3.5
     = 112 GFLOPS（单核）
```

**实际可达**：
- 手写汇编：~100 GFLOPS（90%）
- Highway 优化代码：~80-90 GFLOPS（70-80%）
- 普通 SIMD 代码：~50-60 GFLOPS（45-55%）

## 3. 内存系统优化

### 3.1 缓存层次结构

**典型的 Cache 配置（Intel Core i7）**：

| 层次 | 大小 | 延迟 | 带宽 |
|------|------|------|------|
| L1 Data | 32 KB | 4-5 cycles | ~200 GB/s |
| L2 | 256 KB | 12 cycles | ~100 GB/s |
| L3 | 8 MB | 40-50 cycles | ~50 GB/s |
| Main Memory | 16 GB | 100-200 cycles | ~40 GB/s |

**Cache Line**：
- 大小：64 字节
- 含义：CPU 每次从内存读取一个 cache line
- AVX2 向量：32 字节（半个 cache line）

### 3.2 Cache-Friendly 编程

#### 原则 1: 顺序访问

```cpp
// 坏的访问模式：跨步太大
for (size_t i = 0; i < count; i += 1024) {  // 跨 4KB
  data[i] = 0;  // 每次访问都 miss
}

// 好的访问模式：顺序
for (size_t i = 0; i < count; ++i) {
  data[i] = 0;  // 利用 cache line 预取
}
```

#### 原则 2: 数据局部性

```cpp
// 坏的：Array of Structures (AoS)
struct Particle {
  float x, y, z;     // 位置
  float vx, vy, vz;  // 速度
  float mass;        // 质量
};

Particle particles[1000];

// 更新位置：只需要 x,y,z 和 vx,vy,vz
for (auto& p : particles) {
  p.x += p.vx * dt;  // 加载了 mass（浪费带宽）
  p.y += p.vy * dt;
  p.z += p.vz * dt;
}

// 好的：Structure of Arrays (SoA)
struct Particles {
  float x[1000], y[1000], z[1000];
  float vx[1000], vy[1000], vz[1000];
  float mass[1000];
};

Particles particles;

// 向量化更新位置
const ScalableTag<float> d;
const size_t N = Lanes(d);

for (size_t i = 0; i < 1000; i += N) {
  auto x = Load(d, &particles.x[i]);
  auto vx = Load(d, &particles.vx[i]);
  auto dx = Mul(vx, Set(d, dt));
  Store(Add(x, dx), d, &particles.x[i]);
  // 同样处理 y, z
}
```

#### 原则 3: Cache Blocking（分块）

```cpp
// 矩阵乘法：C = A * B (N x N)

// 朴素实现：Cache miss 很多
for (size_t i = 0; i < N; ++i) {
  for (size_t j = 0; j < N; ++j) {
    float sum = 0;
    for (size_t k = 0; k < N; ++k) {
      sum += A[i][k] * B[k][j];  // B 按列访问，cache miss
    }
    C[i][j] = sum;
  }
}

// Cache Blocking 实现
constexpr size_t BLOCK = 64;  // 适配 L1 Cache

for (size_t ii = 0; ii < N; ii += BLOCK) {
  for (size_t jj = 0; jj < N; jj += BLOCK) {
    for (size_t kk = 0; kk < N; kk += BLOCK) {
      // 小块矩阵乘法，数据留在 L1 Cache
      for (size_t i = ii; i < std::min(ii + BLOCK, N); ++i) {
        for (size_t j = jj; j < std::min(jj + BLOCK, N); ++j) {
          float sum = C[i][j];
          for (size_t k = kk; k < std::min(kk + BLOCK, N); ++k) {
            sum += A[i][k] * B[k][j];
          }
          C[i][j] = sum;
        }
      }
    }
  }
}

// 性能提升：3-5x
```

### 3.3 预取 (Prefetch)

```cpp
// 手动预取
template <class D>
void ProcessWithPrefetch(D d, const float* input, float* output, size_t count) {
  const size_t N = Lanes(d);
  constexpr size_t PREFETCH_DISTANCE = 8;  // 预取 8 个向量之后的数据

  for (size_t i = 0; i < count; i += N) {
    // 预取未来的数据
    if (i + PREFETCH_DISTANCE * N < count) {
      Prefetch(&input[i + PREFETCH_DISTANCE * N]);
    }

    // 处理当前数据
    auto v = Load(d, &input[i]);
    v = /* 复杂计算 */;
    Store(v, d, &output[i]);
  }
}
```

**预取策略**：
- **T0**: 预取到所有 Cache 层（最激进）
- **T1**: 预取到 L2/L3，不进入 L1
- **T2**: 预取到 L3，不进入 L1/L2
- **NTA**: Non-Temporal，不进入 Cache（用于流式访问）

```cpp
// x86 预取 intrinsics
_mm_prefetch(ptr, _MM_HINT_T0);   // 预取到 L1
_mm_prefetch(ptr, _MM_HINT_T1);   // 预取到 L2
_mm_prefetch(ptr, _MM_HINT_NTA);  // 不进入 Cache
```

### 3.4 对齐优化

```cpp
// 测量对齐的影响
void BenchmarkAlignment() {
  const size_t SIZE = 1024 * 1024;

  // 对齐的数据
  auto aligned = AllocateAligned<float>(SIZE);

  // 非对齐的数据（偏移 1 字节）
  auto buffer = AllocateAligned<float>(SIZE + 1);
  float* unaligned = reinterpret_cast<float*>(
    reinterpret_cast<char*>(buffer.get()) + 1
  );

  const ScalableTag<float> d;
  const size_t N = Lanes(d);

  // 测试对齐访问
  auto start = std::chrono::high_resolution_clock::now();
  for (size_t iter = 0; iter < 1000; ++iter) {
    for (size_t i = 0; i < SIZE; i += N) {
      auto v = Load(d, &aligned[i]);  // 对齐的 Load
      Store(v, d, &aligned[i]);
    }
  }
  auto end = std::chrono::high_resolution_clock::now();
  double aligned_time = std::chrono::duration<double>(end - start).count();

  // 测试非对齐访问
  start = std::chrono::high_resolution_clock::now();
  for (size_t iter = 0; iter < 1000; ++iter) {
    for (size_t i = 0; i < SIZE; i += N) {
      auto v = LoadU(d, &unaligned[i]);  // 非对齐的 LoadU
      StoreU(v, d, &unaligned[i]);
    }
  }
  end = std::chrono::high_resolution_clock::now();
  double unaligned_time = std::chrono::duration<double>(end - start).count();

  printf("Aligned: %.3f ms\n", aligned_time * 1000);
  printf("Unaligned: %.3f ms\n", unaligned_time * 1000);
  printf("Slowdown: %.2fx\n", unaligned_time / aligned_time);
}

// 典型结果（AVX2）：
// Aligned: 125.3 ms
// Unaligned: 156.7 ms
// Slowdown: 1.25x  （25% 性能损失）
```

## 4. 算法级优化

### 4.1 算法选择

**原则：选择 SIMD 友好的算法**

#### 示例 1: 排序

```cpp
// 标量排序：std::sort
// - 基于比较的排序（快速排序/堆排序）
// - 大量分支，不适合 SIMD

// SIMD 排序：Highway VQSort
// - 使用 Sorting Networks（固定比较序列，无分支）
// - 向量化的分区
// - 5-10x 比 std::sort 快
```

#### 示例 2: 搜索

```cpp
// 线性搜索（SIMD 友好）
template <class D>
int Find(D d, const float* data, size_t count, float target) {
  const size_t N = Lanes(d);
  auto vtarget = Set(d, target);

  for (size_t i = 0; i < count; i += N) {
    auto v = Load(d, &data[i]);
    auto mask = Eq(v, vtarget);

    if (AnyTrue(d, mask)) {
      // 找到了，确定具体位置
      for (size_t j = 0; j < N; ++j) {
        if (data[i + j] == target) return i + j;
      }
    }
  }
  return -1;  // 未找到
}

// 二分搜索（不适合 SIMD）
// - 大量分支
// - 数据依赖
// - 向量化困难
```

### 4.2 循环展开

```cpp
// 版本 1: 无展开
for (size_t i = 0; i < count; i += N) {
  auto v = Load(d, &input[i]);
  v = Process(d, v);
  Store(v, d, &output[i]);
}

// 版本 2: 2x 展开
for (size_t i = 0; i < count; i += 2*N) {
  auto v0 = Load(d, &input[i]);
  auto v1 = Load(d, &input[i + N]);

  v0 = Process(d, v0);
  v1 = Process(d, v1);

  Store(v0, d, &output[i]);
  Store(v1, d, &output[i + N]);
}

// 版本 3: 4x 展开
for (size_t i = 0; i < count; i += 4*N) {
  auto v0 = Load(d, &input[i + 0*N]);
  auto v1 = Load(d, &input[i + 1*N]);
  auto v2 = Load(d, &input[i + 2*N]);
  auto v3 = Load(d, &input[i + 3*N]);

  v0 = Process(d, v0);
  v1 = Process(d, v1);
  v2 = Process(d, v2);
  v3 = Process(d, v3);

  Store(v0, d, &output[i + 0*N]);
  Store(v1, d, &output[i + 1*N]);
  Store(v2, d, &output[i + 2*N]);
  Store(v3, d, &output[i + 3*N]);
}
```

**展开的好处**：
1. 减少循环开销（分支预测、计数器更新）
2. 增加指令级并行（ILP）
3. 减少依赖链长度
4. 更好的指令调度

**展开的代价**：
1. 代码体积增大（可能影响 I-Cache）
2. 寄存器压力增大
3. 余项处理更复杂

**最佳展开因子**：
- 通常 2-4x
- 取决于 Process 的复杂度
- 需要实测

### 4.3 融合操作

```cpp
// 差的：多次遍历
for (size_t i = 0; i < count; i += N) {
  auto v = Load(d, &data[i]);
  v = Mul(v, Set(d, 2.0f));
  Store(v, d, &data[i]);
}

for (size_t i = 0; i < count; i += N) {
  auto v = Load(d, &data[i]);
  v = Add(v, Set(d, 1.0f));
  Store(v, d, &data[i]);
}

// 好的：融合为一次遍历
for (size_t i = 0; i < count; i += N) {
  auto v = Load(d, &data[i]);
  v = Mul(v, Set(d, 2.0f));
  v = Add(v, Set(d, 1.0f));
  Store(v, d, &data[i]);
}

// 性能提升：2x（减少了一半的内存访问）
```

### 4.4 避免分支

```cpp
// 差的：分支
for (size_t i = 0; i < count; i += N) {
  auto v = Load(d, &data[i]);

  // 分支预测失败会很慢
  if (condition[i]) {
    v = Mul(v, Set(d, 2.0f));
  } else {
    v = Add(v, Set(d, 1.0f));
  }

  Store(v, d, &output[i]);
}

// 好的：使用掩码
for (size_t i = 0; i < count; i += N) {
  auto v = Load(d, &data[i]);
  auto mask = LoadMaskBits(d, condition[i]);

  auto v_mul = Mul(v, Set(d, 2.0f));
  auto v_add = Add(v, Set(d, 1.0f));

  v = IfThenElse(mask, v_mul, v_add);  // 无分支选择

  Store(v, d, &output[i]);
}
```

## 5. 编译器优化技巧

### 5.1 编译选项

```bash
# GCC/Clang 推荐选项
```

### 5.2 __restrict 关键字

```cpp
// 告诉编译器指针不重叠
void Add(const float* __restrict a,
         const float* __restrict b,
         float* __restrict c,
         size_t count) {
  // 编译器可以激进优化，因为 a, b, c 不会重叠
  for (size_t i = 0; i < count; ++i) {
    c[i] = a[i] + b[i];
  }
}

// 对比：无 __restrict
void Add(const float* a, const float* b, float* c, size_t count) {
  // 编译器必须假设指针可能重叠
  // 例如：a 和 c 可能指向同一块内存
  for (size_t i = 0; i < count; ++i) {
    c[i] = a[i] + b[i];  // 每次都要重新加载 c[i]（因为可能被修改）
  }
}
```

**何时使用内联汇编**：

- 需要使用非常特殊的指令
- 已经验证编译器无法优化的瓶颈

**大多数情况不需要**：
- 现代编译器非常智能
- Highway 的抽象已经足够高效
- 手写汇编难以维护

```cpp
#include <benchmark/benchmark.h>

// Google Benchmark 示例
static void BM_VectorAdd(benchmark::State& state) {
  const size_t count = state.range(0);
  auto a = AllocateAligned<float>(count);
  auto b = AllocateAligned<float>(count);
  auto c = AllocateAligned<float>(count);

  // 初始化数据
  for (size_t i = 0; i < count; ++i) {
    a[i] = static_cast<float>(i);
    b[i] = static_cast<float>(i * 2);
  }

  const size_t N = Lanes(d);

  for (auto _ : state) {
    for (size_t i = 0; i < count; i += N) {
      auto va = Load(d, &a[i]);
      auto vb = Load(d, &b[i]);
      auto vc = Add(va, vb);
      Store(vc, d, &c[i]);
    }

    benchmark::DoNotOptimize(c.get());  // 防止编译器优化掉
  }

  state.SetBytesProcessed(state.iterations() * count * 3 * sizeof(float));
  state.SetItemsProcessed(state.iterations() * count);
}

BENCHMARK(BM_VectorAdd)->Range(1024, 1<<20);
BENCHMARK_MAIN();
```

### 6.4 性能计数器

```cpp
// 使用 RDTSC 测量周期数（x86）
inline uint64_t ReadTSC() {
  uint32_t lo, hi;
  __asm__ __volatile__("rdtsc" : "=a"(lo), "=d"(hi));
  return (static_cast<uint64_t>(hi) << 32) | lo;
}

// 测量函数
template <typename Func>
uint64_t MeasureCycles(Func&& func, size_t iterations = 100) {
  // 预热
  for (size_t i = 0; i < 10; ++i) {
    func();
  }

  uint64_t start = ReadTSC();
  for (size_t i = 0; i < iterations; ++i) {
    func();
  }
  uint64_t end = ReadTSC();

  return (end - start) / iterations;
}

// 使用
auto cycles = MeasureCycles([&]() {
  MyVectorizedFunction(data, count);
});

printf("Cycles: %lu\n", cycles);
printf("Cycles per element: %.2f\n", cycles / static_cast<double>(count));
```

### 7.2 案例 2: 字符串搜索

```cpp
// Boyer-Moore 的向量化版本
template <class D>
int FindSubstring_SIMD(D d, const char* text, size_t text_len,
                       const char* pattern, size_t pattern_len) {
  const size_t N = Lanes(d);

  if (pattern_len == 0 || pattern_len > text_len) return -1;

  // 创建首字符向量
  auto first_char = Set(d, pattern[0]);

  for (size_t i = 0; i <= text_len - pattern_len; i += N) {
    // 加载文本
    auto text_vec = LoadU(d, reinterpret_cast<const uint8_t*>(&text[i]));

    // 比较首字符
    auto mask = Eq(text_vec, first_char);

    // 检查匹配
    if (AnyTrue(d, mask)) {
      // 找到潜在匹配，逐一验证
      alignas(64) uint8_t lanes[MaxLanes(d)];
      Store(text_vec, d, lanes);

      for (size_t j = 0; j < N && i + j <= text_len - pattern_len; ++j) {
        if (lanes[j] == pattern[0]) {
          // 验证完整模式
          if (std::memcmp(&text[i + j], pattern, pattern_len) == 0) {
            return i + j;
          }
        }
      }
    }
  }

  return -1;  // 未找到
}

// 性能对比（1MB 文本，短模式）：
// std::string::find: 1.2 ms
// SIMD: 0.3 ms
// 加速比: 4x
```

### 7.3 案例 3: 矩阵乘法

```cpp
// 高度优化的矩阵乘法（简化版）
void MatMul_Optimized(const float* A, const float* B, float* C,
                      size_t M, size_t N, size_t K) {
  const ScalableTag<float> d;
  const size_t lanes = Lanes(d);

  // Cache blocking 参数
  constexpr size_t MC = 256;  // 适配 L2
  constexpr size_t KC = 128;
  constexpr size_t NC = 4096; // 适配 L3

  for (size_t jj = 0; jj < N; jj += NC) {
    for (size_t kk = 0; kk < K; kk += KC) {
      for (size_t ii = 0; ii < M; ii += MC) {
        // 小块矩阵乘法
        for (size_t i = ii; i < std::min(ii + MC, M); ++i) {
          for (size_t j = jj; j < std::min(jj + NC, N); j += lanes) {
            // 向量化内积
            auto sum = Zero(d);

            for (size_t k = kk; k < std::min(kk + KC, K); ++k) {
              auto a_val = Set(d, A[i * K + k]);
              auto b_vec = Load(d, &B[k * N + j]);
              sum = MulAdd(a_val, b_vec, sum);
            }

            // 累加到 C
            auto c_vec = Load(d, &C[i * N + j]);
            c_vec = Add(c_vec, sum);
            Store(c_vec, d, &C[i * N + j]);
          }
        }
      }
    }
  }
}

// 性能对比（1024x1024）：
// 朴素: 2.5 GFLOPS
// OpenBLAS (BLAS库): 45 GFLOPS
// 优化SIMD + blocking: 35-40 GFLOPS
```

## 总结

### 性能优化检查清单

#### 算法层面
- [ ] 选择 SIMD 友好的算法（避免分支、数据依赖）
- [ ] 使用 SoA 而非 AoS 布局
- [ ] 融合多个循环，减少内存遍历次数
- [ ] Cache blocking（分块）大数据集

#### SIMD 层面
- [ ] 使用多个累加器打破依赖链
- [ ] 循环展开（2-4x）
- [ ] 使用 FMA（`MulAdd`）而非分离的 `Mul` + `Add`
- [ ] 避免标量-向量转换
- [ ] 使用掩码代替分支

#### 内存层面
- [ ] 确保数据对齐（使用 `AllocateAligned`）
- [ ] 顺序访问内存（利用预取）
- [ ] 手动预取（对于大跨步访问）
- [ ] 避免 false sharing（多线程）

#### 编译器层面
- [ ] 使用 `-O3 -march=native`
- [ ] 使用 `__restrict` 提示指针不重叠
- [ ] 使用 `HWY_LIKELY`/`HWY_UNLIKELY` 提示分支
- [ ] 避免过早优化，先测量后优化
